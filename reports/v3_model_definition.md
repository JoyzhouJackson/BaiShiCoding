# V3 动态滚动模型修订说明

V3保留V2的3小时时间刻度、每6小时周期滚动、0/6/12小时常规到货、48小时规划窗口及最长72小时观察期。物理约束、货物完整送达和已执行决策不可修改仍为硬约束。

## 服务水平

按产品设置非负短缺变量：

`准时吨数 + 服务短缺吨数 >= 目标服务率 × 产品总吨数`。

加急、普通和经济件的目标服务率仍为98%、95%和90%；短缺惩罚分别为300、150和75成本单位/吨。晚到货物同时按原有30、15和7.5成本单位/吨·时段计算延误成本。延误成本刻画迟到程度，服务短缺惩罚刻画整体承诺违约，两者分别记录。

## 离散异常有效性

车辆故障的时刻和数量由算例固定。事件发生时，从最新计划在该时刻实际位于节点的可用自有车辆中确定一辆故障车；不存在的节点车辆不能被扣减。节点选择按算例编号确定性抽样，结果写入 `realized_event`。

紧急撤单的时刻和总吨数由算例固定。具体撤单明细在事件发生时从尚未发运的货物中确定，撤单后需求不得小于已经发运的吨数。撤单货物删除本身不计算货物改道成本。

## 变更成本与动态总成本

每次周期或事件重调度都和紧邻的上一版计划比较：

- 车辆任务变化为未来任务数量的绝对变化；改变线路或时刻表现为取消原任务并增加新任务。
- 货物改道量使用两版计划共同存在、尚未完成货物在候选行程分配上的半L1距离。新增需求和撤销量不进入该指标。
- 单次变更惩罚继续使用已审核的10%参考计划成本比例，车辆任务与货物改道各占50%，并按各自计划规模归一化。

每一步输出 `change_metrics`、`incurred_change_cost` 和 `cumulative_change_cost`。最终 `episode_objective` 只计算一次完整运输与货物成本、一次最终服务短缺惩罚，再加全过程累计变更成本，避免重复累计每次滚动的计划成本。

## 输出解释

`actual.objective` 是最后一次MILP调用的计划目标，仅用于解释该次求解；四种方法正式比较应使用顶层 `episode_objective` 和 `episode_objective_components`。
